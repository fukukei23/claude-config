# tech-clip — X等の気になりを解析・蓄積→ガイド化パイプライン

## トリガーワード
「これクリップ」「クリップして」「あとで調べて」「気になりメモ」「メモっておいて」（URL・ワード・OSSリンク等の材料を伴う時）・`/tech-clip`

※ 材料なしの単なる質問・事実確認（「これ見て」で即答を求める等）では発火しない。**「蓄積したい」という意図がある時だけ**。

## 目的
X等で見つけたワード・URL・OSSを、その場で解析して**書き溜める**。断片が集まりテーマが固まったらガイド（見返せる形）に仕立てる。流れ:
```
材料を貼る → tech-clip（解析+クリップ追記） → テーマ固まったら make-guide（被りチェック→ガイド化）
```

## フロー

### STEP 1: 材料の把握
ユーザーが貼った材料を分類:
- **URL（記事/投稿/docs）** → WebFetch で本文取得・要点抽出
- **OSSリポジトリURL** → README・スター・ライセンスを確認（gh CLI可）
- **裸ワード（キーワードのみ）** → Web検索1回で定義・文脈を取得

解析は**最小限**（1取得+1行サマリ）に抑える。その場で完璧に調べるのは本スキルの役割でない（ガイド化時に深掘りする）。

### STEP 2: 気になりクリップへの追記
`~/projects/obsidian-ssot/30_RESEARCH/気になりクリップ.md` の該当テーマセクション（無ければ新設）に1エントリ追記:

```markdown
### <テーマ名>（エントリ数: N）
- **YYYY-MM-DD** — <1行サマリ>（<::タグ1::タグ2>）
  - 出典: <URL または「X投稿@user」>
  - 備考: <あれば1行・ガイド化候補/関連エントリ等>
```

- 追記後 commit+push（`*/30` auto-sync を待たない・クリップは時間感度高め）:
  ```bash
  cd ~/projects/obsidian-ssot && git add 30_RESEARCH/気になりクリップ.md && git commit -m "clip: <テーマ>に1件追加" && git push
  ```

### STEP 3: ガイド化判断（毎回・省略不可）
追記後、そのテーマの**エントリ数と被りを機械確認**してから判断を提示:

```bash
# エントリ数確認
grep -c '^\- \*\*' ~/projects/obsidian-ssot/30_RESEARCH/気になりクリップ.md
```

- **エントリ数 ≥ 5 または テーマが1ガイド分の骨格を持つ** → 「このテーマ、ガイドにできます。make-guide に繋ぎますか？」と提案
- **まだ少ない** → 「クリップしました（現N件）。5件前後でガイド化提案します」と1行だけ報告

ガイド化は必ず `make-guide` 経由（STEP 1.5 の既存ガイド被りチェックが自動で走る・本スキルは被り判定をしない）。

## 注意
- **解析の深掘り禁止**: 1エントリ1行サマリ+出典まで。その場で徹底調査するのはガイド化時（YAGNI）
- **シークレット混入禁止**: 貼られた材料にAPIキー等が含まれていれば値をマスクしてから記録
- **気になりクリップ.mdはインボックス**: 永続正典ではない。ガイド化されたら該当エントリに「→ ガイド化済み: <URL>」1行を残し、クリップ本体は肥大化しないよう随時整理
- 30日触られていないテーマセクションは削除候補（resume-session等で気付いたらユーザーに提案）

## 関連
- `make-guide` — ガイド化の入口（STEP 1.5 既存ガイドスキャンで被り判定）
- `ssot-search` — 既存知識との重複確認
- `30_RESEARCH/` — Web調査ファクトの保管場所（本クリップはそのインボックス）
