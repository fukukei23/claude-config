# tech-clip — X等の気になりを解析・蓄積→ガイド化パイプライン

## トリガーワード
「これクリップ」「クリップして」「あとで調べて」「気になりメモ」「メモっておいて」（URL・ワード・OSSリンク等の材料を伴う時）・`/tech-clip`

**発火条件（AND・2026-08-20レビューで明文化）**:
1. 材料がある: ユーザー発言にURL（x.com/github.com等）・固有名詞ワード・OSSリンクが含まれる **— URL単体の無言投下も含む**
2. 蓄積意図が読める: 「あとで」「クリップ」「メモ」等の語、または無言URL投下（=蓄積以外の意図が薄い）

※ 即答を求める質問（「これ見てどう?」等）では発火しない。迷ったら1回「クリップしますか?」と聞く。

## 目的
X等で見つけたワード・URL・OSSを、その場で解析して**書き溜める**。断片が集まりテーマが固まったらガイド（見返せる形）に仕立てる。流れ:
```
材料を貼る → tech-clip（解析+クリップ追記） → テーマ固まったら make-guide（被りチェック→ガイド化）
```

**気になりクリップ.mdの位置づけ**: SSOT分類上は**作業中キャッシュ**（一次資料でない・ガイド化後は参照残すのみ）。ssot-search の検索対象だが weight 低（正式記録はガイド化先 or 01_DECISIONS）。

## フロー

### STEP 1: 材料の把握（呼び出し上限: WebFetch 3回・Web検索 2回まで）
ユーザーが貼った材料を分類:
- **一般URL（記事/docs/blog）** → WebFetch で本文取得・要点抽出
- **X/Twitter投稿URL** → ※WebFetchでは本文取得できない前提。**ユーザーが貼った文面・引用があればそれをサマリの材料にする**。文面も無い場合は「本文取得できず・ユーザー補足待ち」の仮エントリでクリップし、1行補足を依頼
- **OSSリポジトリURL** → README・スター・ライセンスを確認（gh CLI可・失敗時はWeb検索にフォールバック）
- **裸ワード（キーワードのみ）** → Web検索1回で定義・文脈を取得

解析は最小限（1取得+1行サマリ）に抑える。その場で完璧に調べるのは本スキルの役割でない（ガイド化時に深掘りする）。**取得失敗でフローを中断しない**（仮エントリで継続）。

### STEP 2: 気になりクリップへの追記
`~/projects/obsidian-ssot/30_RESEARCH/気になりクリップ.md` の該当テーマセクションに1エントリ追記:

```markdown
### <テーマ名>（エントリ数: N）
- **YYYY-MM-DD** — <1行サマリ>（<::タグ1::タグ2>）
  - 出典: <URL または「X投稿@user」>
  - 備考: <あれば1行・ガイド化候補/関連エントリ等>
```

- **テーマセクション新設時**: 既存テーマセクションの一覧をまず確認し、似たテーマがあればそちらへ追記（類似名の乱立防止）
- 追記後 commit+push（`*/30` auto-sync を待たない）:
  ```bash
  cd ~/projects/obsidian-ssot && git commit-scoped -m "clip: <テーマ>に1件追加" -- 30_RESEARCH/気になりクリップ.md && git push
  ```

### STEP 3: ガイド化判断（毎回・省略不可・本スキルの責務は「数えて繋ぐ」だけ）
tech-clipが行うのは (a) エントリ数カウント (b) make-guideへの引き継ぎ提案 のみ。**被り判定・ガイド起案は make-guide のSTEP 1.5が独占担当**（二重実装防止）:

```bash
grep -c '^\- \*\*' ~/projects/obsidian-ssot/30_RESEARCH/気になりクリップ.md
```

- **エントリ数 ≥ 5**（目安: 背景/既存調査/選択肢/推奨/注意点という1ガイドの最小骨格≒5要素）**または既存ガイドに足せそうなテーマ** → 「make-guide に繋ぎますか?」と提案（既存ガイドがありそうなら早めに提案して無駄な蓄積を防ぐ）
- **まだ少ない** → 「クリップしました（現N件）。5件前後でガイド化提案します」と1行だけ報告

**ついで整理（毎回・機械的）**: 最終更新が30日超のテーマセクションを grep で抽出し、あれば「アーカイブしますか?」と1行提案:
- アーカイブ先: `30_RESEARCH/_archive/気になりクリップ-YYYY-MM.md` へ移動（**削除しない**——忘れていた重要テーマの消失防止・本アーカイブの削除はユーザー確認付きのみ）

## 注意
- **解析の深掘り禁止**: 1エントリ1行サマリ+出典まで
- **シークレット混入禁止**: 貼られた材料にAPIキー等が含まれていれば値をマスクしてから記録
- **気になりクリップ.mdはインボックス（キャッシュ）**: ガイド化されたら該当エントリに「→ ガイド化済み: <URL>」1行を残す。肥大化したらアーカイブ運用で整理

## 関連

- `oss-first` — OSS候補の本格評価はこちら（tech-clipは1行クリップのみ）
- `30_RESEARCH/` — Web調査ファクトの保管場所（本クリップはそのインボックス）
