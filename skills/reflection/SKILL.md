# reflection — 週次リフレクション生成（Phase2）

spec: `obsidian-ssot/docs/superpowers/specs/2026-08-16-reflection-skill-phase2-design.md`
対象読者: 生成するLLM自身。手順を厳密に守ること（品質は手順で担保）。

## トリガーワード
「リフレクション」「今週の振り返り」「思考癖まとめて」/reflection

## Phase 0: 対象週決定（1実行=1週）

```bash
REF_DATE=$(TZ=Asia/Tokyo date -d "last sunday" +%F)
WEEK=$(TZ=Asia/Tokyo date -d "$REF_DATE" +%G-W%V)
ls ~/projects/obsidian-ssot/40_CAREER/リフレクション/weekly/$WEEK.md 2>/dev/null && echo "存在: 対象は次の未生成完了週"
```

- 対象 = **未生成の完了週のうち最も古い週**（通常は上記 $WEEK）
- 対象週ファイルが既に存在する場合: ユーザーに「再生成（置換）か別の週か」を確認
- **1回の実行で生成するのは1週分のみ**（複数週未生成でもまとめ生成はしない）

## Phase 1: 想起トリガー（記憶鮮度の機械的補完）

対象週（月〜日）の日記 `10_DAILY/YYYY-MM-DD.md` を読み、**主要トピックを箇条書きで先に列挙**してから本文生成に入る（いきなり書き始めない）。

## Phase 2: 前週Wファイル読込

- 前週 = 対象週のISO週−1（`date -d "$REF_DATE -7 days" +%G-W%V`）
- 前週ファイルが存在しない場合（初回・スキップ週）: 繰越・アドバイス評価をスキップし新規作成として処理

## Phase 3: 4要素生成

テンプレ: `40_CAREER/リフレクション/weekly/_テンプレート.md` / **品質基準（few-shot）: `weekly/2026-W33.md`** を必ず読む

1. 📊 作業の傾向・時間の使い方（集中プロジェクト・反復パターン・時間帯）
2. 🧠 思考・意思決定の癖（sentaku/multi-llm-review使用傾向・重視した原則）
3. ⚠️ 繰り返す課題・弱点（過去週との連続性に注意）
4. 💡 CCからのアドバイス（翌週実行可能な具体アクション）

**思考ルール（厳守）**:
- 「なぜ」を3回深掘りする。**事象の羅列を禁止**（日記の要約コピーレベルで終わらない）
- 前週のCCアドバイスは **実行/未実行/部分実行 をすべて明記**（自己擁護禁止・未実行を正直に）
- 持ち越しは2セクションに物理分離: 「前週からの繰越（評価対象）」と「次週への申し送り（新規作成）」
- commitハッシュ・日時など具体例を必ず付ける

## Phase 4: 品質チェック（機械判定・生成物に適用）

§4.5チェックリスト5項目（事実羅列でないか/具体例あり/CC実行可能/前回一貫性/持ち越し明示）＋以下:

| # | チェック | 閾値 |
|---|---|---|
| ① | 具体エピソード（日付・固有名詞付き）の引用数 | ≥3件 |
| ② | 前週Wファイルと同一・類似の文 | ≤2文 |
| ③ | 前週アドバイスの実行/未実行/部分実行の明記 | すべて |
| ④ | 🧠セクションの主語ラベル（🤖LLM作業側/👤ユーザー判断）付与（2026-08-27レビュー指摘で追加） | 混在段落すべて |

- **軽微な⚠️**（例: ②が3文）: 警告行を付けてPhase 5へ
- **重大な⚠️**（①<3件）: **会話内にドラフトを表示して停止**。ファイル作成せずユーザーの修正指示を待つ→修正後にPhase 5へ

## Phase 5: commit & push（未承認Top3込み・1回のcommit）

1. `weekly/$WEEK.md` 作成（frontmatter: type/week/period/generated/sources + 本体 + 末尾に `## Top3候補（未承認）` セクション）
2. 日記（対象週の日付ファイル群）に `## 週次リフレクション反映 ($WEEK)` 見出しでサマリー追記。再生成時は**同見出し（$WEEK厳密一致）のセクションを置換**（冪等）
3. `_INDEX.md` frontmatter に `pending_top3: $WEEK` を追加
4. commit & push（obsidian-ssot・**git add はファイル個別指定**）:
   `git add 40_CAREER/リフレクション/weekly/$WEEK.md 40_CAREER/リフレクション/_INDEX.md 10_DAILY/<対象日付群>` → `git commit -m "reflection: $WEEK 週次リフレクション生成（Top3未承認）"` → `git push`

## Phase 6: Top3承認（D′案・先に記録して後から消す）

未承認状態は既にcommit済み。therefore:

- 同一セッションにユーザーがいる場合: Top3の3行ドラフトを表示 → `y`/修正指示を待つ
- **承認時**: `_INDEX.md` の「気づきTop3」を差替 + `pending_top3` を削除 + `top3_last_updated: $WEEK` を更新 → 別commit & push（`reflection: $WEEK Top3承認反映`）
- ユーザーが反応しなければ**そのまま終了**（何もしなくてよい — 次回 resume-session が検知して再依頼する）

## Phase 7: 品質レビュー（3機・恒久・2026-08-27W34実績の恒久化）

W34初回の2機レビュー実績を得て、以後の生成に品質レビューを標準組み込みする（ユーザー指示・2026-08-27）。

- **呼出**: `multi-llm-review --triple`（MiniMax+Gemini+OpenRouter free）でWファイル全文と直近週Wファイルを比較レビューさせる
- **観点固定**: ①主語の区別（🤖LLM作業側 vs 👤ユーザー判断） ②事実精度（日記との整合・出典） ③分析深度（「なぜ」の深掘り）+ 統合スコア5段階（5=前週同等以上）
- **縮退**: 3機呼ぶが **M≥2で続行**（3機目失敗で生成を止めない・multi-llm-reviewの縮退判定に従う）
- **統合**: 採用指摘をWファイルへ適用 → review_log.md + revised_proposal.md を `00_SYSTEM/マルチLLMレビュー/<日付>_reflection-<WEEK>品質レビュー/` に保存 → commit & push
- **報告**: 生成完了報告には統合スコア・適用修正・人手修正残を添える（Phase7の判断をユーザーに委ねない）
