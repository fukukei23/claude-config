# compare-options スキル（選択肢比較・淘汰・推奨）

## 概要

選択肢が複数ある場面で、**深掘り比較によってLLM側に最適案を淘汰させ、推奨1案に収束させる**。

判断負担の軽減 + 判断の質の向上が核心の価値。
専門知識のないユーザーが「問い方1つでLLMの分析を深度化できる」パターンを再利用可能にする。

```
選択肢群 → [深掘り比較] → 淘汰 → 推奨(1案) → 承認
                ↑                    ↓（不十分なら）
                └── 再反続（深さを上げて）
```

## トリガーワード

- 「比較して」「比べて」「それぞれ深掘りして」「それぞれ詳しく」
- 「メリデリ教えて」「メリット・デメリットは」「長所短所は」
- 「お勧めは？」「どれがいい？」「一番良いのは」
- 「ちゃんと比較して」「もっと深く」「徹底的に」「重要な判断なので」
- 「過去の判断と照合」「前にどう決めたっけ」「一貫性確認」
- `/compare-options`

## 4段階の深さ（要求or収束状況で昇格）

| 段階 | 名前 | 内容 | トリガー |
|---|---|---|---|
| **L1: Light** | 固定3点 | 各案の「メリット・デメリット・推奨」を表で比較 | デフォルト |
| **L2: Deep** | 評価軸マトリクス | コスト/確実性/リスク/工数 等の軸で採点マトリクス | 「もっと深く」「ちゃんと比較して」 |
| **L3: Dialectic** | 複数LLM弁証論 | 案ごとに別agentが擁護し弁証論→統合 | 「徹底的に」「重要な判断なので」 |
| **L4: Precedent** | 過去判断照合 | SSOT `01_DECISIONS/` から類似判断を検索→比較軸に「過去との整合/乖離」を追加 | 「過去の判断と照合」「前にどう決めたっけ」「一貫性確認」 |

- 基本は **L1** から。ユーザーが「もっと深く」で L2、それでも絞れなければ L3 へ自動昇格。
- **L4 は他段階と直交**（L1+L4 等、任意の段階に重ねて発火可能）。

## L1: Light（デフォルト出力テンプレート）

```markdown
## 🔍 選択肢比較：[トピック名]

### 選択肢
- **A: [案A名]** — [一言説明]
- **B: [案B名]** — [一言説明]
- **C: [案C名]** — [一言説明]（3つ目がある時のみ）

### 📊 比較表

| 軸 | A: [案A] | B: [案B] | (C: [案C]) |
|---|---|---|---|
| ✅ メリット | [利1], [利2] | [利1] | [利1] |
| ❌ デメリット | [欠1] | [欠1], [欠2] | [欠1] |
| 💰 コスト | [高/中/低] | [高/中/低] | — |
| 🎯 確実性 | [高/中/低] | [高/中/低] | — |
| ⚡ 工数 | [大/中/小] | [大/中/小] | — |

### ⭐ 推奨：[案X名]
**理由：** [淘汰の決め手を1〜2行で]
**次のステップ：** [どう進めるか]

> もっと深く比較しますか？（「もっと深く」で評価軸マトリクス昇格 / 「徹底的に」で弁証論 / 「過去と照合」でL4）
```

## L2: Deep（評価軸マトリクス）

ユーザーが「もっと深く」「ちゃんと比較して」で昇格。

1. その判断に適した **評価軸**（コスト/確実性/リスク/工数/拡張性/学習コスト 等）を3〜5個設定
2. 各案を各軸で **5段階（または重み付き）採点**
3. 重み付き合計スコアで **定量淘汰**
4. スコア表 + 淘汰理由を出力

```markdown
### 📐 評価軸マトリクス（重み付き）

| 軸(重み) | A: [案A] | B: [案B] | 備考 |
|---|---|---|---|
| コスト(×3) | 4 = 12 | 2 = 6 | Aは既存資産活用 |
| 確実性(×2) | 3 = 6 | 5 = 10 | Bは実績あり |
| 拡張性(×2) | 5 = 10 | 3 = 6 | Aは将来変更に強い |
| **合計** | **28** | **22** | → Aを採用 |
```

> 軸の選定はLLM/ユーザーが都度設定（自動決定はしない＝YAGNI）。

## L3: Dialectic（複数LLM弁証論）

ユーザーが「徹底的に」「重要な判断なので」で昇格。重要度が高くL2でも決まらない時に。

1. 案ごとに **別agent（または別視点）が擁護側** として最强の主張を展開
2. 各擁護案に対し **反論** を立てる
3. 反論を統合し **合成案/最終推奨** を導出
4. 弁証論の過程（主張→反論→統合）を要約して出力

> agent数の自動調整はしない（固定 or ユーザー指定＝YAGNI）。
> Claude Code単独の場合は「視点を分けて自問自答」で代用。

## L4: Precedent（過去判断照合）

「過去の判断と照合」「前にどう決めたっけ」「一貫性確認」で発火。**任意の段階(L1〜L3)に重ねて使用可**。

### 動作
```
1. ssot-search スキル（または search.py）で 01_DECISIONS/ から類似判断を検索
   python3 ~/.claude/scripts/ssot/search.py "<トピック>" --ssot-dir ~/projects/obsidian-ssot/01_DECISIONS --top 5
2. 過去の決定・理由・結果を抽出
3. 現在の比較に「過去判断との整合性」軸を追加
4. 矛盾があれば明示:
   「過去は A を選んだ（理由: △△）。今回は B を推奨。差分理由: 〇〇」
```

ヒット0件なら「過去に類似判断なし」として L1〜L3 の結果で判定（L4は必須ではない）。

### 副次価値
- **SSOT活用促進**: `01_DECISIONS/` が「書きっぱなし」から「判断時に参照される」資産へ
- **説明性向上**: 「なぜ前回と違う判断か」が常に説明できる
- **一貫性保証**: 同じような判断でブレない

## 2モード

### 対話モード（ユーザー主導）= 本スキルの基本
- 選択肢が出た状態でユーザーがトリガー
- 現段階（基本L1）で比較→推奨。「もっと深く」で昇格
- ユーザー承認で確定

### 自律モード（LLM自問自答）
- 実装中（loop-eng / dev-cycle）に「選択肢が複数ある判断」に直面しユーザー不在の時
- LLMが自力で L1 → 候補残れば L2 → それでも絞れなければ L3 へ自動昇格
- 重要度が高い判断は自動で L4 発火（過去との整合を確認してから採用）
- 1案に絞れたら採用 / 上限(L3まで)到達で最推奨案を採用し**判断根拠を記録に残す**
- 発火ポイントの定義は `00_SYSTEM/共通ルール/自律開発ループ.md` 側

## 棲み分け（関係スキル）

```
「提案して」 → teian（浅: さっと2-3案提示）
       ↓ 深掘りしたい
「比較して/深掘りして」 → compare-options（中: 深掘り比較→淘汰→推奨）← 本スキル
       ↓ 設計全体を詰めたい
「ちゃんと設計したい」 → brainstorming（深: 要件抽出から設計全体）
```

- **teian** は浅い提案の入口。「深掘り」要求で本スキルへ委譲
- **brainstorming** は設計全体。本スキルは「既に出た選択肢の比較」に特化
- **ssot-search** は L4 の検索を委譲先として使う（新規検索機能は作らない）

## 禁止事項

- **選択肢を提示するだけのteianと混同しない** — 本スキルは「比較→淘汰→推奨1案」まで責任を持つ
- **深さを勝手にL3まで上げない** — ユーザー要求 or 収束失敗時に限る（YAGNI）
- **推奨を出さずに終わらない** — 比較だけして判断を丸投げしない

## 成功基準

- 選択肢提示場面で「深掘りして」の一言で、メリデリ+推奨が1画面で返ること（L1）
- L4で過去判断と照合でき、乖離時に差分理由が明示されること
- teianから「深掘り」で本スキルに委譲できること
