# make-guide — ガイド系作成のディスパッチャ（振り分け）

## トリガーワード
「ガイド作って」「教科書作って」「チートシート作って」「語彙帳作って」「チュートリアル作って」「/make-guide」

## 目的
ユーザーは「読む系ガイド」と「引く系チートシート」の違いを覚えなくてよい。
内容からLLMが判定し、**必ず1回確認を挟んで**から適切なスキル（guide-builder / textbook-guide）に分岐する。
本スキル自体はガイドを生成しない（判定・確認・分岐のみ。生成は各スキルに任せる）。

## フロー

### STEP 1: 内容の把握
直前の会話文脈から「作りたい内容」を把握する。
（ユーザーは会話の中で「これ残したい」と思って「作って」と言うことが多い。文脈が不足する場合のみ「何について作りますか？」と1回だけ聞く。）

### STEP 2: 読む系 / 引く系 の判定
内容から下表で判定する:

| 読む系 → guide-builder | 引く系 → textbook-guide |
|---|---|
| 手順を順に学ぶ・通読する | 必要な時に引く・検索する |
| 体系的・複数ページ構成 | 一覧・早見表・単一HTML |
| 例: 「Claude Codeの使い方全体」「Docker入門」 | 例: 「Gitコマンド一覧」「regex早見表」「用語集」 |

### STEP 3: 確認（必須・1回必ず挟む）

**判定に確信がある場合:**
> 「これは【読む系 / 引く系】ですね。【guide-builder / textbook-guide】で進めてよろしいですか？」

**判定に迷う場合**（例: 「Gitのガイド」は読む系にも引く系にもなる）:
両者のメリット/デメリット＋おすすめを提示して選択:

```
この内容は読む系にも引く系にもできます。

📖 読む系（guide-builder・複数ページ）
  メリット: 手順を最初から学べる・体系立つ
  デメリット: さっと引けない

📋 引く系（textbook-guide・単一HTML）
  メリット: 必要な時にすぐ引ける・コンパクト
  デメリット: 通読には向かない

おすすめ: 【〇〇系】（理由: 〜）
どちらにしますか？
```

### STEP 4: 分岐
ユーザーが承認したら、対応するスキルを呼び出す:
- **読む系** → `guide-builder`
- **引く系** → `textbook-guide`

ユーザーが「いや、こっちで」と言ったら、即そちらに分岐（再確認は不要）。

## 注意
- **必ず1回は確認を挟む**（誤判定防止・ユーザーの提案の核心）
- make-guide 自体はHTMLを生成しない。判定・確認・分岐のみ。
- 会話文脈がない場合のみ「何について作りますか？」と聞く（それ以外は聞き直さない）。
- 分岐先のスキルが index.html / 全体マップのN冊更新まで面倒を見る（本スキルは関与しない）。
