# oss-first — 自作前の既存OSS探索ゲート（車輪の再発明防止）

## トリガーワード
「これ作りたい」「新しいツール作りたい」「実装したい」「〇〇を作る」（新規の制作意図）・`/oss-first`

※ バグ修正・既存機能改修では発火しない。**ゼロから作る意図がある時だけ**。

## 目的
X投稿「車輪の再発明」論（@voidwarriorchan・2026-08-18）と curl_cffi 事例（2026-08-18: atelierに3ヶ月前から実装済みだったのに「Keepa月$19必須」と誤認）の再発防止を機構化する。

**「ないから作る」の「ない」を、記憶・樂観でなく機械的検索で証明してから設計に入る。**

```
制作意図 → ①SSOT内探索 → ②GitHub/Web探索 → ③評価 → ④判定提示 → ⑤証跡 → 設計へ
```

## フロー

### STEP 1: 課題の抽象化（検索の前準備・必須）
作りたいものを**技術名でなく課題名**の語彙に翻訳する（知らない技術名は検索クエリに入れられない・2026-08-18教訓）:

- 例: 「Amazon在庫監視ツール」→ 課題語彙: `スクレイピング` `bot対策` `HTTP取得` `在庫監視`（同義語・上位概念を含める）
- 抽象化語彙は3語以上用意する

### STEP 2: SSOT内探索（既存実装・過去判断の確認）
```bash
cd ~/projects/obsidian-ssot
ls 01_DECISIONS/ | grep <キーワード>
grep -rl "<課題語彙1>\|<課題語彙2>" 01_DECISIONS/ 00_SYSTEM/ | head
```
→ 自分の資産に既存実装・過去の判断（却下された方式含む）があれば先に提示（`_INDEX.md` の dataview はCLIで展開されないので実ファイル直参照・LLMサボりバイアス防止.md「タスク再着手時の必須検索」準拠）。

### STEP 3: GitHub/Web探索（外部の既存資産）
- **GitHub検索**: `gh search repos "<課題語彙>" --sort stars --limit 10` または Web検索 `site:github.com <課題語彙>`
- **一般検索**: Web検索 `<課題語彙> OSS tool`・`<課題語彙> open source`
- 代替候補（SaaS・CLI・ライブラリ）も含める。「完璧に思い通りではないが近いものはだいたい存在する」

### STEP 4: 評価（候補ごとに1行ずつ）
| 評価軸 | 見るポイント |
|---|---|
| 活発性 | スター数・最終コミット日（1年以上停止は注意） |
| ライセンス | MIT/Apache-2.0 は改造自由・GPL は組み合わせ注意 |
| 改造容易性 | 規模・言語・ドキュメント・自分が読めるか |
| 適合度 | 要件の何割を満たすか・足りない部分の自作量 |

### STEP 5: 判定提示（ユーザー確認）
検索・評価結果を表にして、以下の3択を**推奨案付き**で提示:

```
🚗 車輪チェック結果: 「<作りたいもの>」
| 候補 | 活発性 | ライセンス | 適合度 | 一言 |
|---|---|---|---|---|
| OSS-A | ★1.2k・先週更新 | MIT | 90% | ほぼそのまま使える |
| OSS-B | ... | ... | ... | ... |

判定案: 【そのまま使う / fork改良 / 自作】（理由: 〜）
⚠️ 自作を選ぶ場合: 「探したが要件Xを満たすもの無し」という検索証跡が必要（楽観判断での自作=再発明リスク）
どれにしますか？
```

**自作を選ぶ場合の条件**: 上記の検索証跡（候補一覧と「なぜダメだったか」）を残す。満足欲求・学習目的の自作は正当（本人の明言があれば可）。

### STEP 6: 証跡記録
判定は `ssot-record` スキルで記録（tech_tags に課題の抽象化語彙を含める・将来の横断検索用）。既存「新規技術タスク着手時の必須検索」（`@rules/_shared/LLMサボりバイアス防止.md`）を拡張する形で動く（置き換えではない）。

## 注意
- **検索の省略禁止**: 「たぶん既存にない」は検証回避バイアス。STEP 2/3 の実行コマンドと結果を省略しない
- ** Lightweight運用**: 小さいツール（数10行のスクリプト等）で明らかに既存を探すまでもない場合は「探索省略の理由1行」を添えて簡略可（ゲート過剰適用防止）
- 判定後の設計・実装は brainstorming / executing-plans 等の既存フローへ（本スキルはゲート専任）
