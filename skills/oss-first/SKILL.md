# oss-first — 自作前の既存OSS探索ゲート（車輪の再発明防止）

## トリガーワード
`/oss-first`（最優先）・「これ作りたい」「新しいツール作りたい」「実装したい」（**ソフトウェアをゼロから作る意図の表明時のみ**）

**発火しない cases（誤発火防止・2026-08-20レビューで厳格化）**:
- バグ修正・既存機能改修・リファクタリング
- 「ガイドを作る」「文書を作る」「ルールを作る」等の**非ソフトウェア制作**（文書・コンテンツ・音楽等）
- 「こういうツールあるといいな」等の願望・雑談（能動的な制作着手表明でない）
- brainstorming 進行中の設計議論（ゲートは設計着手の直前に1回だけでよい）

## 目的
「ないから作る」の「ない」を、記憶・樂観でなく機械的検索で証明してから設計に入る。

```
制作意図 → ①SSOT内探索 → ②GitHub/Web探索 → ③評価 → ④判定提示 → ⑤証跡 → 設計へ
```

## フロー

### STEP 1: 課題の抽象化（検索の前準備・必須）
作りたいものを**技術名でなく課題名**の語彙に翻訳する（知らない技術名は検索クエリに入れられない・2026-08-18教訓）。

抽象化語彙は3語以上。**構成要件（単なるキーワード羅列不可）**: ①課題ドメイン（監視/可視化/同期等）②対象・規模感（個人/データ量等）③既存手段の限界点（なぜ既存で足りないか）の3要素を語彙がカバーしていること。

### STEP 2: SSOT内探索（既存実装・過去判断の確認）
```bash
cd ~/projects/obsidian-ssot
ls 01_DECISIONS/ | grep <キーワード>
grep -rl "<課題語彙1>\|<課題語彙2>" 01_DECISIONS/ 00_SYSTEM/ | head
```
→ 自分の資産に既存実装・過去の判断（却下された方式含む）があれば先に提示（`_INDEX.md` の dataview はCLIで展開されないので実ファイル直参照・LLMサボりバイアス防止.md「タスク再着手時の必須検索」準拠）。

### STEP 3: GitHub/Web探索（外部の既存資産・呼び出し上限: 検索合計3回まで）
- **GitHub検索**: `gh search repos "<課題語彙>" --sort stars --limit 10` — **ghが未インストール・未認証・失敗したら直ちにWeb検索 `site:github.com <課題語彙>` にフォールバック（フロー停止禁止・コマンド失敗を理由に探索を諦めない）**
- **一般検索**: Web検索 `<課題語彙> OSS tool`・`<課題語彙> open source`
- 代替候補（SaaS・CLI・ライブラリ）も含める。「完璧に思い通りではないが近いものはだいたい存在する」

### STEP 4: 評価（候補ごとに1行ずつ）
| 評価軸 | 見るポイント |
|---|---|
| 活発性 | スター数・最終コミット日（1年以上停止は注意） |
| ライセンス | MIT/Apache-2.0 は改造自由・GPL は組み合わせ注意 |
| 改造容易性 | 規模・言語・ドキュメント・自分が読めるか |
| 適合度 | 要件の何割を満たすか・足りない部分の自作量 |

### STEP 5: 判定提示（ユーザー確認）
検索・評価結果を表にして、以下の3択を**推奨案付き**で提示:

```
🚗 車輪チェック結果: 「<作りたいもの>」
| 候補 | 活発性 | ライセンス | 適合度 | 一言 |
|---|---|---|---|---|
| OSS-A | ★1.2k・先週更新 | MIT | 90% | ほぼそのまま使える |

判定案: 【そのまま使う / fork改良 / 自作】（理由: 〜）
どれにしますか？
```

**自作を選ぶ場合の証跡（最小フォーマット）** — 探した記録を ssot-record 記録本文に必ず含める:
```
## 探索証跡（自作判断の根拠）
- 検索クエリ: <クエリ1> / <クエリ2>（実行日: YYYY-MM-DD）
- 候補と却下理由: OSS-A（要件X不足）/ OSS-B（1年停止）/ 該当なし（<課題語彙>）
```
学習目的・満足欲求の自作は正当（本人の明言があれば可・その旨を証跡に1行）。

### STEP 6: 証跡記録
判定は `ssot-record` スキルで記録（tech_tags に課題の抽象化語彙を含める・将来の横断検索用）。既存「新規技術タスク着手時の必須検索」（`@rules/_shared/LLMサボりバイアス防止.md`）を拡張する形で動く（置き換えではない）。

## 注意
- **検索の省略禁止**: 「たぶん既存にない」は検証回避バイアス。STEP 2/3 の実行コマンドと結果を省略しない
- **簡略は例外的3条件のみ**（2026-08-20レビューで厳格化——「探すまでもない」という主観判断は検索結果に基づかない=サボりバイアス):
  ①社内固有・個人固有の業務ロジックで外部OSSの適用範囲外 ②既存資産の利用が技術的に不可能な環境制約 ③数行のグルー処理（標準コマンド・既存関数の組み合わせ）
  - 上記いずれかの場合も **最低1回のWeb検索（`<課題語彙> CLI one-liner` 等）は強制**し、「簡略理由+検索結果1行」を記録に残す
- **シークレット混入禁止**: 検索結果・貼られた材料にAPIキー等が含まれていればマスクして記録
- 判定後の設計・実装は brainstorming / executing-plans 等の既存フローへ（本スキルはゲート専任）
