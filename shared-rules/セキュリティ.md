# セキュリティルール（共通・WSL/Windows両環境）

## APIキー・シークレット
- APIキー**値**を会話・ファイル・コミットに書き込まない（キー名はOK・値はNG）
- `settings.json` / `settings.local.json` / `.secrets.env` の**値**を出力・表示禁止
- キー名のみ確認: `python3 -c "import json; print(list(json.load(open('<path>'))['env'].keys()))"`
- **シークレットのコマンド渡しルール（2026-07-29追加・TOKEN混入事故対策）**:
  - シークレット（APIキー・トークン）は**コマンドライン引数に直接書かない**（`source ~/.secrets.env` で環境変数読込 → `$変数` 参照）
  - ❌ `curl -H "Authorization: Bot <生値>"` / ✅ `source ~/.secrets.env && curl -H "Authorization: Bot $DISCORD_BOT_TOKEN"`
  - 理由: 権限ポップアップで「今後許可」を選ぶと**コマンド全文（埋め込み値含む）が allow リストに永続化**するため（2026-06-10 Discord TOKEN混入事故の真因・[[2026-07-29_権限モードsentaku-TOKEN露出経路根本対策]]）

## 禁止オペレーション
- `rm -rf *`, `git push --force`, `sudo`, `DROP/DELETE *` は実行禁止
- `.git/`, `.env`, `core/`, `lib/`, `tools/`, `docs/` の削除・移動禁止
- `rm`（ファイル削除）・`git push` は実行前にふくけい確認
- **削除系は ask 正規経路を使う（deny抜け道に頼らない・2026-07-30事案）**:
  - `rm -rf *`（ワイルドカード全削除）は deny（自動拒否）。`mv` 等で deny を回避する抜け道は**保護形骸化リスクで常用NG**（緊急時限定）
  - ファイル削除は **個別指定 `rm <file>...`（-rf無・ワイルドカード無）→ ask（ふくけい確認）→ 許可で実行** の正規経路を使う（deny/ask/allow 3層モデル・settings.json 設計思想に沿う）
  - 理由: 「禁止されたから無理」でなく「確認を通せば安全に消せる」。deny/ask/allow 現状一覧は `00_SYSTEM/セキュリティ設定ハブ.md`（整備中）参照
