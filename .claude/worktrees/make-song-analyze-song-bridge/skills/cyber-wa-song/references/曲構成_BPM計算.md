# 曲構成・小節・BPMと曲長の計算

> 曲長は **BPM × 小節数** で完全に決まる（音楽理論）。生成前に逆算できる。LLMの制約ではない。

## 核心公式（4/4拍子）

```
1小節の長さ(秒) = (60 ÷ BPM) × 4
秒数            = 小節数 × 4拍 × (60 ÷ BPM)
小節数          = (分数 × BPM) ÷ 4
```

## テンポ×曲長 連動表（スキル核心）

小節数を固定すると、テンポで秒数が自然に変動（ユーザー指摘「速いなら20秒、スローなら30秒」）:

| 小節数(4/4) | BPM120(速) | BPM90(中) | BPM70(遅) |
|---|---|---|---|
| 8小節（フック） | 16秒 | 21秒 | 27秒 |
| 16小節（Verse） | 32秒 | 43秒 | 55秒 |

## ヒップホップ標準曲構造

| パート | 小節 | 役割 |
|---|---|---|
| Intro | 4-8 | 雰囲気作り（インスト多い） |
| Verse（バース/ラップ） | **16** ←標準 | ストーリー・スキル見せ場。曲で一番長い |
| Pre Chorus | 4-8 | Verse→Chorusのブリッジ |
| Chorus/Hook（サビ） | 8 | キャッチーな反復 |
| Bridge | 4-8 | 変化・転調 |
| Outro | 4-8 | 締め |

**標準フル構成（Verse3回パターン）:**
```
Intro(8) → Verse1(16) → Chorus(8) → Verse2(16) → Chorus(8) → Verse3(16) → Chorus(8) → Outro(8)
合計: 80-96小節 → BPM90で約3分30秒〜4分
```
業界標準は **「16小節Verse / 8小節Chorus」**。これを3セット回すのが王道。

## Music-2.6 実測の圧縮挙動（重要・理論と実測は乖離する）

| 検証 | 歌詞量 | 理論小節 | 実測duration | 到達率 |
|---|---|---|---|---|
| 曹仁v1 | ~500字 | (設計なし) | 109秒 | − |
| 曹仁v2 | ~1100字 | 136 | 154秒 | **62%** |
| 曹仁v3 | +間奏タグ3回 | − | 181秒 | +27秒延長 |

**AIは設計値の60-70%にしか届かない**（Verse3回構造を2Verse分に圧縮する傾向）。

### 長尺化ベストプラクティス（公式テンプレ準拠）
1. **`[Verse 1][Verse 2][Verse 3]` 番号付き**（`[Verse]`のみは圧縮される）
2. **`(掛け声)` 括弧バックボーカル**（歌詞量増＋演出）
3. **各Verse完全差別化**（類似圧縮回避）
4. **`[Break]` でVerse間区切り**（構造認識強化）

### 無意味な手法（検証済み）
- promptに"4 minutes"明記 → ❌ 無効（曹仁v3実証）
- "exact BPM 130"明記 → ❓ 効果不明

### 実務目安（BPMと自然な曲長）
| BPM帯 | 自然な曲長 | 目安小節数 |
|---|---|---|
| 70-90（ゆったり/メロ） | 4分半-5分 | 113-130小節 |
| 90-110（標準） | 4分-4分半 | 100-120小節 |
| 120-140（速い/攻め） | 3分半-4分 | 90-110小節 |
| 140+（高速） | 3分-3分半 | 75-95小節 |

**教訓**: 目標曲長を固定せず、BPMに合った自然な長さを受け入れる。無理に伸ばすと息切れする。

## APIパラメータ（長さ制御の決定的結論）

- **長さ(duration)/BPM指定paramはAPIにもMCPにも存在しない**（100%確定）
- MCP payloadは5項目のみ（model/prompt/lyrics/audio_setting/output_format）
- 残るレバーは `prompt` ＋ `lyrics` の構造タグ **のみ**
- 価格は長さ非依存: **$0.15/曲**（1分でも5分でも同額）
