# 開発ワークフロー

このドキュメントは、軽量開発品質管理ガイドの実際の運用フローを定義します。

## 概要

開発フローは以下の2つに分類されます:
- **Tier 2（通常タスク）**: 即座に実装開始
- **Tier 1（高リスクタスク）**: 簡易仕様確認後に実装開始

## Tier 2 フロー（通常タスク）

```
ユーザー指示
  ↓
直接実装
```

### 例

```
ユーザー: ログイン画面の UI を作って
Claude: [Tier 2 タスクと判定]
        [直接実装開始]
```

**判断基準**: Tier 1 キーワードに該当しないタスク

### Tier 2 タスクの例
- UI コンポーネントの作成
- 既存機能の軽微な修正
- ログ出力の追加
- テストコードの追加
- ドキュメント更新
- リファクタリング（ロジック変更なし）

## Tier 1 フロー（高リスクタスク）

```
ユーザー指示
  ↓
Tier 1 Validator Agent 自動起動
  ↓
簡易仕様確認（3項目）
  1. 何を作るか
  2. 主要な制約
  3. 影響範囲
  ↓
ユーザー承認
  ↓
実装開始
  ↓
重要判断の発生
  ↓
Decision Recorder Agent 自動起動
  ↓
決定記録を作成
  ↓
実装完了
  ↓
Code Reviewer Agent（オプション）
  ↓
レビュー結果の報告
```

### 例

```
ユーザー: JWT 認証機能を実装して

Claude: [Tier 1 キーワード「JWT」「認証」を検出]
        [Tier 1 Validator Agent 自動起動]
        
Tier 1 Validator:
このタスクは Tier 1（認証関連）です。
実装前に簡易仕様を確認させてください。

1. 何を作るか: 
   JWT トークンによるユーザー認証機能

2. 主要な制約:
   - アクセストークン有効期限: 15分
   - リフレッシュトークン有効期限: 7日
   - トークン保存先: httpOnly Cookie

3. 影響範囲:
   - 新規ファイル作成: auth/jwt.py, middleware/auth.py
   - 既存ファイル修正: なし

この内容で実装を開始してよろしいですか？

ユーザー: OK

Claude: [実装開始]
        [auth/jwt.py を作成]
        [middleware/auth.py を作成]
        
        [重要な設計判断が発生]
        「リフレッシュトークンのローテーション戦略を決定」
        
        [Decision Recorder Agent 自動起動]
        
Decision Recorder:
重要な判断を記録します。以下を確認させてください:
- 決定内容: リフレッシュトークンローテーションを採用
- 背景: セキュリティ強化のため
- 理由: トークン漏洩時のリスク軽減
...

Claude: [実装完了]

ユーザー: レビューして

Claude: [Code Reviewer Agent 起動]
        [auth/jwt.py と middleware/auth.py をレビュー]
        
Code Reviewer:
# コードレビュー結果
[セキュリティ、パフォーマンス、保守性の観点から分析]
```

### Tier 1 タスクの例
- 認証・認可機能の実装
- 決済フローの追加
- データ移行スクリプト
- 公開 API の追加
- セキュリティ設定の変更
- 本番デプロイ設定

## 決定記録フロー

```
ユーザー: [技術的判断を表明]
  ↓
Decision Recorder Agent 自動起動
  ↓
決定内容の詳細を確認
  - 背景
  - 理由
  - トレードオフ
  - 代替案
  ↓
docs/decisions/ に連番付きファイル作成
  ↓
完了通知
```

### 例

```
ユーザー: PostgreSQL を採用することにした

Claude: [Decision Recorder Agent 自動起動]

Decision Recorder:
重要な判断を記録します。以下を確認させてください:

1. 決定内容: PostgreSQL をメインデータベースとして採用
2. 背景: なぜこの決定が必要でしたか？
3. 理由: なぜ PostgreSQL を選びましたか？
4. トレードオフ: メリットとデメリットは？
5. 代替案: 他に検討した選択肢は？

ユーザー: [情報を提供]

Decision Recorder:
決定記録を作成しました:
docs/decisions/001-use-postgresql.md
```

## エージェント起動トリガー

### Tier 1 Validator Agent
**自動起動条件**:
- Tier 1 キーワードを検出
  - 認証、認可、ログイン、パスワード、トークン
  - 決済、支払い、課金
  - データ移行、スキーマ変更
  - 公開API、エンドポイント
  - 暗号化、セキュリティ
  - 本番環境、デプロイ

### Code Reviewer Agent
**起動トリガー**:
- ユーザーが明示的に「レビューして」と指示
- ユーザーが「今週のコード」「今日のコミット」を確認要求

### Decision Recorder Agent
**自動起動条件**:
- ユーザーが「〜を採用」「〜に決めた」と判断を表明
- Tier 1 実装中に重要な設計判断が発生

## 並列処理の活用

### 複数ファイルのレビュー
```
Code Reviewer Agent が起動
  ↓
変更ファイルを特定: [file1.py, file2.py, file3.py]
  ↓
並列でレビュー実行
  ├── Code Reviewer (file1.py)
  ├── Code Reviewer (file2.py)
  └── Code Reviewer (file3.py)
  ↓
結果を統合して報告
```

**メリット**:
- レビュー時間の短縮
- GUI で進捗を視覚的に確認
- 大量のファイルを効率的に処理

## バックグラウンド実行

### 長時間タスクの場合
```
ユーザー: 全ファイルをレビューして

Claude: [大量のファイルを検出]
        バックグラウンドでレビューを実行します。
        完了時に通知します。
        
[メインセッションで他の作業を継続可能]

[レビュー完了時]
通知: コードレビューが完了しました
```

**適用場面**:
- 大規模なコードレビュー
- テストスイートの実行
- データ移行のシミュレーション

## フロー図

### 全体フロー
```
ユーザー指示
  ↓
Tier 1? ─── No ──→ 直接実装（Tier 2）
  ↓ Yes
Tier 1 Validator 起動
  ↓
簡易仕様確認（3項目）
  ↓
ユーザー承認
  ↓
実装開始
  ↓
重要判断? ─── Yes ──→ Decision Recorder 起動
  ↓ No                     ↓
実装継続               決定記録作成
  ↓                         ↓
実装完了 ←───────────────┘
  ↓
レビュー要求? ─── Yes ──→ Code Reviewer 起動
  ↓ No                        ↓
完了                     レビュー結果報告
                              ↓
                          完了
```

## 実装時の注意事項

### Tier 1 タスク
1. **保守的に判定**: 疑わしい場合は Tier 1 扱い
2. **仕様確認は最小限**: 3項目のみで十分
3. **承認を待つ**: ユーザーの承認なしに実装開始しない
4. **重要判断を記録**: 些細な選択は記録不要

### コードレビュー
1. **建設的なフィードバック**: 批判的すぎない
2. **重大度を明示**: Critical / High / Medium / Low
3. **具体的な修正提案**: 必ず改善案を含める
4. **ポジティブな点も**: 良い点も積極的にフィードバック

### 決定記録
1. **重要な判断のみ**: データベース選定、アーキテクチャ設計など
2. **客観的に記録**: 感情的表現を避ける
3. **十分な文脈**: 将来の参照に役立つよう詳細に記録
4. **代替案も記載**: なぜ採用しなかったかを明記

## デスクトップ版の活用

### 視覚的フィードバック
- サイドバーで各エージェントの進捗を確認
- 進捗バーでタスクの完了度を監視
- エージェントごとに色分け表示（Tier 1: 黄、レビュー: 青、記録: 緑）

### 並列セッション管理
- 複数のエージェントを同時に実行
- タブで各エージェントを管理
- 必要に応じて切り替え

### プロアクティブ実行
- 適切なタイミングで自動的にエージェントを起動
- ユーザーの指示を先読みして提案
- 実装完了時にレビューを提案

## まとめ

このワークフローにより:
- **Tier 1 タスクの安全性確保**: 実装前の仕様確認
- **効率的なコードレビュー**: 並列処理で時間短縮
- **判断の透明性**: 重要な決定を自動記録
- **視覚的な進捗管理**: デスクトップ版の GUI を活用
