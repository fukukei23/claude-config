# プロンプト: コンポーネント抽出＆パッケージ化

> **用途**: リポジトリから価値あるコンポーネントを抽出し、独立パッケージ（pip/npm等）として整備する
> **カテゴリ**: 生成系
> **前提**: `リポ価値抽出.md` で抽出対象を特定済みであること

---

## 実行ステップ

### Step 1: 依存関係グラフの作成
対象コンポーネントが依存する全モジュールを `Grep` と `Read` で特定し、依存関係ツリーを出力する。
各依存を以下の3種類に分類:
- **A. 標準ライブラリ**: そのまま使用
- **B. サードパーティ**: requirements.txt に追加
- **C. プロジェクト内部依存**: 抽出時に置換・除去が必要

### Step 2: 内部依存の切り離し設計
Cの内部依存について、以下のいずれかで解決する方針を決定:
- **インライン化**: 小さなユーティリティは直接組み込む
- **インターフェース化**: 抽象基底クラス/Protocol で疎結合化
- **設定外部化**: ハードコード値を設定ファイル/環境変数へ
- **機能削除**: パッケージに不要な依存機能は切り捨て

### Step 3: パッケージ構造の設計
以下の標準構造で出力:

```
{{PACKAGE_NAME}}/
├── pyproject.toml          # ビルド設定（PEP 621準拠）
├── README.md               # パッケージ説明（英語必須）
├── LICENSE                  # ライセンス（MIT推奨）
├── src/
│   └── {{PACKAGE_NAME}}/
│       ├── __init__.py      # 公開API定義
│       ├── core.py          # メインロジック
│       └── ...              # 必要なモジュール
├── tests/
│   ├── __init__.py
│   ├── test_core.py
│   └── conftest.py
└── examples/
    └── basic_usage.py       # 最小動作例
```

### Step 4: コード抽出と品質整形
抽出したコードに対して以下を実行:
1. **不要なimport削除**: 元プロジェクト固有のimportを除去
2. **型アノテーション追加**: 公開APIの全引数・戻り値に型ヒント
3. **docstring追加**: Google形式でモジュール・クラス・関数にdocstring
4. **エラーハンドリング**: ユーザー向けの明確な例外メッセージ
5. **ログ**: `logging` モジュールで適切なログ出力
6. **定数の外部化**: マジックナンバー・ハードコードURL等を定数として定義

### Step 5: マネタイズ評価
以下の観点でマネタイズ可能性を評価:

```markdown
## マネタイズ評価

### 市場分析
- **競合**: [npm/pip上の既存代替品とその問題点]
- **差別化要因**: [このパッケージの独自の強み]
- **ターゲットユーザー**: [誰が使うか]

### 配布戦略（推奨順）
1. **OSS（MIT）+ 有料サポート**: パッケージ本体は無料、コンサル/SLA付きサポートを有料化
2. **デュアルライセンス**: 個人/小規模は無料、企業利用は商用ライセンス
3. **SaaS API 化**: パッケージをクラウドAPIとして提供し従量課金
4. **Zenn/Note 技術記事**: 技術解説記事で集客→パッケージ導入へ誘導

### マーケティングチャネル
- PyPI/npm への公開
- GitHub README の SEO 最適化
- 技術ブログ（Zenn/Qiita）での紹介記事
- 関連 Discord/Slack コミュニティでの告知
```

### Step 6: 出力物
以下をすべて出力すること:
1. **pyproject.toml** の完全な内容
2. **README.md**（インストール手順、使用例、APIリファレンス）
3. **src/ 以下の全ソースコード**
4. **tests/ のテストコード**
5. **examples/ の使用例**
6. **マネタイズ評価レポート**

---

### ツール活用ガイドライン

1. **Grep**: 対象ファイルの `import` 文を全抽出して依存関係を把握
2. **Read**: 元コードの全行を精読。抽出漏れがないようにする
3. **Agent**: 大規模な依存グラフ追跡やテストコード生成にサブエージェントを活用
4. **Bash**: `grep -r "from\|import"` で依存を機械的に列挙
5. **Write**: 抽出済みファイルの書き出し

### 注意事項
- 元リポジトリのライセンスを確認し、抵触しないこと
- 元リポジトリ固有のビジネスロジック（URL、顧客名、価格等）は一切含めないこと
- セキュリティ上の懸念があるコード（認証情報、内部URL）は除去すること
