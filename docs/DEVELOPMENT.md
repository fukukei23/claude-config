# 軽量開発品質管理ガイド

## 概要

このガイドは、個人開発やスモールチームでの開発における品質管理を最小限の手間で実現するためのフレームワークです。

### 設計思想
- **最小限の手間**: 過度なドキュメントや会議は不要
- **実用性重視**: 実際に使える、形骸化しないルール
- **自動化優先**: Claude Code のエージェント機能で自動判定

## タスクの分類

### Tier 1（高リスクタスク）
以下のいずれかに該当するタスク:

#### 認証・認可関連
- 認証、認可、ログイン、ログアウト
- パスワード、トークン、セッション
- JWT、OAuth、SAML
- 権限、ロール、アクセス制御
- 多要素認証、MFA、2FA

#### 決済・金融関連
- 決済、支払い、課金、請求
- クレジットカード、銀行口座
- 返金、チャージバック
- 金額計算、税金計算

#### データ管理関連
- データ移行、マイグレーション
- スキーマ変更、テーブル変更
- データ削除、一括削除
- バックアップ、リストア

#### 公開API関連
- 公開API、エンドポイント
- APIキー、シークレット
- レート制限、スロットリング
- Webhook

#### セキュリティ関連
- 暗号化、復号化
- ハッシュ化、ソルト
- CSRF、XSS、SQLインジェクション
- セキュリティヘッダー
- CORS設定

#### インフラ・デプロイ関連
- 本番環境、プロダクション
- デプロイ、リリース
- ロールバック、切り戻し
- DNS変更、ドメイン設定

### Tier 2（通常タスク）
Tier 1 に該当しないすべてのタスク:
- UI コンポーネントの作成
- 既存機能の軽微な修正
- ログ出力の追加
- テストコードの追加
- ドキュメント更新

## Tier 1 タスクの処理フロー

### 1. 判定（自動）
Claude Code が Tier 1 キーワードを検出すると、Tier 1 Validator Agent が自動起動します。

### 2. 簡易仕様確認（3項目のみ）
以下の3項目のみを確認:

```
1. 何を作るか: [機能の概要を1-2文で]

2. 主要な制約:
   - [制約1]
   - [制約2]
   - [制約3]

3. 影響範囲:
   - 新規ファイル作成 or 既存ファイル修正
   - 変更対象ファイル: [ファイル名]
```

### 3. ユーザー承認
仕様確認内容を確認し、承認後に実装開始。

### 4. 実装
通常通り実装を進めます。

### 5. 決定記録（自動）
重要な技術的判断が発生した場合、Decision Recorder Agent が自動的に記録します。

### 6. レビュー（オプション）
必要に応じて Code Reviewer Agent でレビューを実施します。

## Tier 2 タスクの処理フロー

1. 直接実装開始
2. 通常通り実装

## エージェントの動作

### Tier 1 Validator Agent
- **起動条件**: Tier 1 キーワードを検出
- **役割**: 簡易仕様確認（3項目）
- **出力**: 仕様確認書（最小限）

### Code Reviewer Agent
- **起動条件**: 
  - ユーザーが「レビューして」と指示
  - ユーザーが「今週のコード」を確認要求
- **役割**: セキュリティ、パフォーマンス、保守性の観点からレビュー
- **出力**: 重大度別の問題リスト + 修正提案

### Decision Recorder Agent
- **起動条件**:
  - ユーザーが「〜を採用」「〜に決めた」と表明
  - Tier 1 実装中の重要な設計判断
- **役割**: 決定内容、背景、理由、トレードオフを記録
- **出力**: `docs/decisions/[連番]-[内容].md`

- サイドバーで各エージェントの進捗を確認

- エージェントごとに色分け表示
  - Tier 1 Validator: 黄色
  - Code Reviewer: 青色
  - Decision Recorder: 緑色

### 並列セッション管理
- 複数のエージェントを同時に実行
- タブで各エージェントを管理
- 必要に応じて切り替え

### プロアクティブ実行
- 適切なタイミングで自動的にエージェントを起動
- ユーザーの指示を先読みして提案
- 実装完了時にレビューを提案

## よくある質問

### Q1. Tier 1 判定が厳しすぎる/緩すぎる場合は？
A. `.claude/rules.md` の Tier 1 キーワードを編集してください。

### Q2. 仕様確認をスキップしたい場合は？
A. Tier 1 タスクでも、ユーザーが「仕様確認不要」と明示すれば直接実装できます。

### Q3. すべてのプロジェクトで同じルールを使いたい
A. グローバル設定（`C:\Users\USER\.claude\`）に配置すれば、すべてのプロジェクトで自動適用されます。

### Q4. プロジェクト固有のルールを追加したい
A. プロジェクトディレクトリに `.claude/rules.md` を作成すれば、グローバル設定に加えてプロジェクト固有のルールが適用されます。

### Q5. エージェントが起動しない場合は？
A. 以下を確認してください:
- `.claude/agents/*.md` が正しく配置されているか
- YAML frontmatter の形式が正しいか
- Claude Code のバージョンが最新か

### Q6. 決定記録が自動作成されない場合は？
A. 明示的に「〜を採用する」「〜に決めた」と表明してください。暗黙の判断は自動検出されません。

## まとめ

このガイドにより:
- **Tier 1 タスクの安全性確保**: 実装前の最小限の仕様確認
- **効率的なコードレビュー**: 並列処理で時間短縮
- **判断の透明性**: 重要な決定を自動記録
- **視覚的な進捗管理**: デスクトップ版の GUI を活用
- **最小限の手間**: 過度なドキュメントや会議は不要

すべてのプロジェクトで自動的に適用されるため、新規プロジェクト開始時の追加作業は不要です。
