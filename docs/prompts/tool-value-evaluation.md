# プロンプト: ツール価値評価（2026年4月基準）

> **用途**: リポジトリ/ツールの現在における価値を多角的に評価し、商用可能性を判定する
> **カテゴリ**: 評価系
> **前提**: Claude Code環境で実行。事前に `repo-deep-analysis.md` でリポジトリ全体を理解済みであることが推奨

---

以下のツール/リポジトリについて、2026年4月現在の技術状況を踏まえて価値を評価せよ。

**対象:** `{{TOOL_NAME}}`
**URL:** `{{TOOL_URL}}` または `{{REPO_URL}}`

Claude Codeのツール（Bash, Glob, Grep, Read, Agent）を駆使してリポジトリを調査した上で、以下の構造化レポートとして出力すること。推測ではなく、実際のコードを読んだ事実のみを記述すること。

```markdown
# ツール価値評価レポート: {{TOOL_NAME}}

## 全体サマリー
- **評価対象URL:** `{{TOOL_URL}}`
- **ツールの概要:** （2〜3文で簡潔に）
- **総合評価ランク:** [S/A/B/C/D]
  - S: 市場独占的価値
  - A: 極めて有用
  - B: 特定用途で有用
  - C: 代替あり、ニッチ価値のみ
  - D: 陳腐化・廃止推奨
- **評価の理由:**
  1. （理由1）
  2. （理由2）
  3. （理由3）

## 詳細評価基準

### 1. ペインポイントの存在
- **評価:** 高 / 中 / 低
- **分析:** このツールが解決する問題は2026年4月において実際に存在するか？AIエディタやエージェントの進化により、その問題はすでに解決済みとなっていないか？

### 2. 代替可能性
- **評価:** 完全代替 / 部分代替 / 代替不可
- **分析:** Claude Code, Cursor, Windsurf, GitHub Copilot等の標準機能で代替可能か？代替する場合、どの設定やプロンプトで再現できるか？

### 3. 独自性
- **評価:** 高 / 中 / 低
- **分析:** 市場に存在しない機能、ドメイン特化型ロジック、独自アーキテクチャは何か？

### 4. 実用性
- **評価:** 高 / 中 / 低
- **分析:** 想定ユーザー層の厚みと市場規模。エッジケースのニッチ需要か、広範な一般開発者向けか？

### 5. 維持コスト vs 提供価値
- **評価:** 優秀 / 釣り合い / 悪い
- **分析:** APIコスト、サーバー維持費、コード保守コストに対して得られる価値が見合っているか？

## 戦略的アクションプラン

### 生存可能なユースケース
- （代替ツールではカバーしきれない具体的ユースケース）

### 改善または転換すべき方向
- （機能追加、ニッチ特化、アーキテクチャ転換の具体的提案）

### 廃止を推奨する場合の理由
- （総合評価C以下の場合に必須。廃止理由と代替手段）

## 商用利用判定
- **判定:** 商用可能 / 商用困難 / 商用不可
- **根拠:** （ライセンス、サードパーティAPI規約、法務リスクを考慮）

### 商用化プロンプト（商用可能な場合）
- **ターゲット顧客:** （具体的なペルソナ）
- **課金モデル:** （サブスク/従量課金/売り切り等）
- **必要な最小改修:** （商用化に必要な開発項目）
- **マーケティングメッセージ:** （1文）
- **競合優位性:** （具体的な差別化ポイント）
```

### ツール活用ガイドライン

1. **Glob & Grep**: エントリーポイント、依存関係（`package.json`, `requirements.txt`等）、ライセンスファイルを検索
2. **Read**: コアロジックを精読し、実装の複雑さと独自性を評価。単なるAPIラッパーでないか確認
3. **Agent**: 複数ファイルを横断的に読み解き、アーキテクチャ全体と保守コストを総合分析
4. **Bash**: `wc -l`（行数）、依存関係スキャン、脆弱性チェックで保守性を定量評価
5. **WebSearch**: 競合ツールの最新状況を確認し、代替可能性を正確に判断

### 分析のポイント

- **陳腐化に注意**: 単純なチャットUIやコード補完ラッパーは2026年時点でデファクトスタンダードに内包済み。加味して評価
- **具体的な代替比較**: 「Claude Codeのカスタムコマンドで再現可能」「Cursorの `.cursorrules` で代替可能」等の解像度で比較
- **コスト意識**: エージェントや長大コンテキストを扱うツールの場合、トークンコストや実行時間のオーバーヘッドを考慮
- **感情論排除**: 技術的事実と市場論理のみで判断。持ち上げる必要はない
